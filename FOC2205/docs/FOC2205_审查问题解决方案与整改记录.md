## 1. P0 级：逐条证据与最终方案

### P0-1 SPI_SendAndReceive 双倍时钟 —— 成立，已按报告修
**证据**：`spi.c` L45-58 —— `SPI_SendAndReceive` 配置 Phase0=TX(tx_bytes)、Phase1(或2)=RX(rx_bytes)，`SPI_Start(PHASE_CNT2/3)` 顺序执行两相 → 同一 nSCS 内总时钟 = (tx+rx) 字节。原代码 `SPI_SendAndReceive(SPI0,2,w,2)`=32clk、`(SPI1,3,0,3)`=48clk。
**器件后果**：DRV8316 p54 "A full 16 SCLK cycles must occur… If the data word … is less than or more than 16 bits, a frame error occurs and the data word is ignored" + STAT2.SPI_SCLK_FLT（p60）。MT6701 24clk 帧被 48clk 冲掉 → CRC 必挂。
**措施**：`drv8316.c` → `SPI_Send(SPI0,2,w)`；`mt6701.c` → `SPI_Send(SPI1,3,0)`。MISO 本来就由 CPLD `spi_mode_wrap` 捕获（`SPIW_RXDATA0/1`），硬 SPI 只当帧发生器，单相发送恰好 16/24 clk。

### P0-2 小端字节序 —— 成立，已按报告修
**证据**：`spi.c` L6 `SPI_Init` 默认 `CTRL = div | SPI_CTRL_LITTLE_ENDIAN`；`spi.h` L180-182 的注释与宏给出铁证——`// SPI flash takes address bytes in reversed order`，`SPI_FLASH_ADDR` 把地址字节在 32 位字内**倒序**存放才能让 flash 收到"命令在前、地址高字节在前"→ 结论：**LITTLE_ENDIAN 模式 = 字内低字节先上线、字节内 MSB 先行**。原 `make_frame` 的高字节（W+A[5:0]+Parity）后上线，DRV8316 会先收到 Data 字节。
**措施**：`make_frame` 返回 `(w<<8)|(w>>8)` 字节交换（报告 §4.1 原样采纳）。MT6701 侧 TX 是 dummy 无影响。

### P0-3 INLx 恒高违反改模式前提 —— 成立，报告修法不可行，改用 INL_EN 方案
**证据**：
- 手册 p20 Table 8-2 下方 Note（原文）：*"Texas Instruments does not recommend changing the MODE pin or PWM_MODE register during operation of the power MOSFETs. **Set all INHx and INLx pins to logic low before changing the MODE pin or PWM_MODE register.**"*
- 手册 p63：CTRL2 [Reset = 60h]，PWM_MODE 复位 = 00b = **6x 模式**（报告此点正确）。
- 手册 p22 Table 8-4（3x 真值表）：`INLx=0 → Hi-Z`（与 INHx 无关）；`INLx=1,INHx=0 → L`；`INLx=1,INHx=1 → H`。

**对报告的两点修正**：
1. 手册原文是 "does not recommend / set low **before** changing"，并非报告所引的 "the register write is IGNORED"——违规后果手册未定义，风险实质成立但措辞过重。
2. **报告建议"至少 10k 下拉接地"是死路**：3x 模式下 INLx=0 = 永久 Hi-Z（Table 8-4 第一行），电机永远无力矩。INLx 必须"改模式时低、运行时高"，恒高恒低都不可行。

**最终方案（已落）**：
- **硬件**：INLA/B/C(28/30/32) 三脚在 PCB 上并联，接 AG32 **PIN_15**（GPIO2_2，QFN32 可用 pad 清单内纯 IO），PIN_15 加 10k 下拉。代价 = 1 个新增 pad + 1 个电阻。
- **固件**：`app_io_init()` 置 INL_EN=0 → `drv8316_init()` 写 CTRL2（此时 INHx=0、INLx=0，完全满足 Note）→ `main()` 自检通过后 `drv_inl_high()` → 3x 正常驱动。
- **两态安全性**：冷启动 = 6x 模式 + INL=0/INH=0 → Hi-Z（Table 8-3）；热复位 = 3x 保持 + INL=0 → Hi-Z（Table 8-4）。均无直通、无力矩。
- **不改板的验证捷径（上板实验 C，不作为设计）**：TI 自己的 3x 应用图（Figure 8-4）就是 INLx→AVDD 恒高，说明恒高时 PWM_MODE 写**可能**实际生效。上板可先直接写 CTRL2 再回读：若 PWM_MODE 位读到 10b 则恒高方案能用（保留 v3 接法）；若读不回或报故障 → 必须按上述改板。注意写 CTRL2 被拒时 SLEW/SDO 配置也会一起丢，验证时以回读为准。

### P0-4 CCR 无限幅 —— 成立，已按报告修
**证据**：`foc.c` 旧代码浮点转 `(int32_t)` 后直写 CCR；负数 → 0xFFFFFFFF → PWM1 模式 CNT<CCR 恒真 → 该相 100% 常高。虽然当前算法 `v∈[-vmax,+vmax]`、`k=ARR/(2·vmax)` 数学上不越界，但浮点异常/后续改动无保护。
**措施**：`pwm3ph_set()` 三相 0~ARR 饱和限幅（报告 §4.3 原样采纳），覆盖包括对齐路径在内的所有调用点。

## 2. P1 级：逐条证据与最终方案

### P1-1 缺零位/方向标定 —— 成立；对已落实现再修两处
**证据**：磁铁与定子 d 轴随机偏角 θ₀ 下，电角度不加偏置 = 力矩矢量错位（90° 错位全部变 d 轴发热，负阻尼半平面飞车）。这是常识级要求，报告正确。
**对已落代码的两处修正**（另一模型的对齐函数 `foc_align_sensor` 已存在但有 bug）：
1. **限幅畸变**：`v_limit_q=3000`（0.732V）而 `v_align=1.2V` → 对齐三相 CCR 撞限幅 → 空间矢量畸变，零位标不准。修：`v_limit_q = 8192`（2.0V，任意 VM≥7V 都安全）、`v_align = 0.6×vmax`（永不饱和）。
2. **方向未标定**：`sensor_direction` 恒 +1，装反 = 正反馈飞车。修：对齐后在电气 +90° 再加一拍矢量，比较传感器 raw_e 偏移落在哪个半圆，自动写 `sensor_direction`（±1），main 打印确认。
**保留**：对齐 400ms 吸合 + 32 帧 CRC 通过样本取均值，思路正确。

### P1-2 nSLEEP 死锁 —— 成立且升级为电源架构问题，报告的固件修法无效
**证据**：
- 手册 p53 §8.4.1.1（原文）：*"In sleep mode, all FETs are disabled, current sense amplifiers are disabled, **buck regulator (if present) is disabled**, the charge pump is disabled, **the AVDD regulator is disabled, and the SPI bus is disabled.**"*
- 手册 p7：`IVMQ`（nSLEEP=0）= 1.5-2.5µA —— 全芯片深度睡眠。
- nSLEEP 片内下拉（150-300k）→ 上电即睡。
- 本设计 v3 §5：MCU VDD33 ← DRV8316 buck 输出 VBK。

**推演**：VM 上电 → nSLEEP 被下拉 = 低 → 睡眠 → buck 关 → MCU 无电 → 永远无法执行 `drv_wake()`。**报告的修法（app_io_init 不调 drv_sleep）修不了这个环——MCU 根本启动不了。** 唯一破环方法：MCU 的 3.3V 来自一个**不经过 nSLEEP 门控**的电源，即从 VM 直接取电的独立 LDO（buck→LDO 级联也不行，睡眠时 buck 本身停）。
**最终方案（已落，接线设计 v4 §5）**：
- 新增独立 3.3V LDO（输入接 VM；VM≤15V 可用 AMS1117-3.3，宽压用 78M33/同级 ≥25V 耐压，≥150mA），供 AG32 VDD33 + MT6701 VDD + nFAULT/nSLEEP 上拉；
- **nSLEEP 加 10k 上拉到 3.3V 主轨**：上电即唤醒 DRV（tWAKE 后 SPI 可用），MCU 复位期 DRV 不会被拉进睡眠；GPIO2_1 保留作 20-40µs 清故障脉冲（拉低后靠上拉回高）；
- **DRV8316 buck 网络不贴**（SW_BK 电感、FB_BK/22µF 全 DNP），CTRL6 写 **0x11**（BUCK_PS_DIS=1 + BUCK_DIS=1）；
- 收益：VM 下限从"buck 要求 >6V（设计留 7V）"放宽到 4.5V（DRV UVLO），2S-6S 均可用。

### P1-3 中心对齐 40kHz 中断 —— 成立；RCR=1 方案有相位陷阱，改波谷门控
**证据**：`gptimer.h` L24 RCR 存在、L40 `CMS` = STM32 语义；中心对齐模式更新事件在上溢+下溢各一次 → 20kHz PWM = 40kHz 中断。低边采样拓扑只有波谷（下桥全开）电流有效，波谷对齐采样是必须的。
**对报告修法的修正**：`RCR=1`（每 2 个更新事件出一次中断）的落点取决于使能顺序——若落在上溢（波峰），**每一次中断都在波峰，配合任何"波谷检查"会把全部有效节拍丢光，电机完全不动**。RCR 相位问题在 AGM 的定时器 RTL 上无法事先确认。
**最终方案（已落）**：`pwm3ph_init` 不配 RCR（保持 40kHz 入口，开销约 2% CPU）；`pwm3ph_update_irq` 入口清 UIF 后判 `GPTIMER0->CNT > ARR/2 → return`——下溢事件后 CNT 刚回绕接近 0，上溢事件后 CNT 停在 ARR 附近，判据与 RCR 相位无关，绝对落在波谷。

## 3. P2 级：逐条证据与最终方案

### P2-1 MT6701 挂 AVDD —— 成立（预算确实紧 + 倒灌路径存在），随 P1-2 一并整改
**证据**：手册 p7 `IAVDD`（External analog regulator load）max = 30mA；AVDD 还要供 DRV 内部电路。v3 把 MT6701（典型 ~7-10mA、max 14mA）挂在 AVDD 上，再叠 INLx 上拉，动态裕度小；且睡眠期 AVDD 关断时 MCU 引脚经 MT6701 ESD 二极管倒灌（P1-2 整改后不再睡眠，此路径消失）。
**措施**：MT6701 VDD 改接独立 LDO 3.3V 主轨（+100nF+TVS 按 MT6701 图-23）；AVDD 只剩 DRV 内部 + VREF 电容，裕量大。INLx 上拉/下拉也随 P0-3 移出 AVDD（10k 下拉到 GND）。

### P2-2 5V EEPROM 跳线 —— 成立，报告的"串 1kΩ"不采纳，直接删跳线
**证据**：
- MT6701 p1："内置 EEPROM（**烧写时需要保证 VDD>4.5V**）"；p32 §8.2：烧写**通过 I²C 接口**进行（写 0xB3→0x09、0x05→0x0A、等 ≥600ms、断电复核），且**务必保持 4.5V<VDD<5.5V**。
- AGRV2K datasheet：IO 为 3.3V LVCMOS/LVTTL，**全文无 5V tolerant**（v3 文档 L129"5.5V 容限"系笔误，已更正）。
- 本板 MT6701 只接了 SSI 三线（CLK/DO/CSN），**根本没有 I²C 通信能力**——板上烧写在架构上就不可行，5V 跳线是摆设且是危险源。
**措施**：删除板上 5V 跳线与相关走线；SSI 模式由 MODE=VDD 决定、出厂默认即可用，本设计**无需烧写 EEPROM**。将来要改 ABZ/UVW 参数 → 离线编程座（I²C+5V）完成后再贴片。报告的 DO 串 1kΩ 方案不采纳：12.5MHz SSI 上升沿 ~10ns，串 1k×走线电容直接毁眼图，且不能防 5V 进入 3.3V 轨。

### P2-3 电流采样阻塞且未进环 —— 成立（架构意图如此），降频遥测
**证据**：`foc_step_isr` 每拍 `current_trigger()+ADC_WaitForEoc`≈1.04µs，而电压模式不消费电流。
**措施**：保留谷底同步采样（这是将来电流环的正确时序），改为每 16 拍一次（~1.25kHz 遥测，单拍阻塞 1.04µs 摊薄到 0.065%）；主循环 500ms 打印。进入电流环时恢复全速。**不做**报告提的 DMA/移出中断——准同时三路采样必须在谷底 ISR 内完成（无 TRGO 触发的硬约束，见接线设计 §7）。
