**审查对象**：FOC2205 力反馈旋钮驱动工程（AG32VF303KCU6 QFN32 + MT6701QT-STD + DRV8316CRRGFR）

## 1. 致命级问题详细分析（P0）

### P0-1: AG32 硬 SPI 双相传输导致时钟数翻倍（32clk 与 48clk）
- **根因分析**：
  AG32 的 SPI 控制器设计源于 Flash/QSPI 控制器结构。在 SDK 的 `framework-agrv_sdk/src/spi.c` 中：
  ```c
  uint32_t SPI_SendAndReceive(SPI_TypeDef *spi, int tx_bytes, const uint32_t tx_data, int rx_bytes) {
    SPI_SetPhaseCtrl(spi, SPI_PHASE_0, SPI_PHASE_ACTION_TX, SPI_PHASE_MODE_SINGLE, tx_bytes);
    ...
    SPI_SetPhaseCtrl(spi, SPI_PHASE_1, SPI_PHASE_ACTION_RX, SPI_PHASE_MODE_SINGLE, rx_bytes);
    SPI_Start(spi, SPI_CTRL_PHASE_CNT2, ...); // 顺序执行 Phase 0 和 Phase 1
  }
  ```
  `SPI_SendAndReceive` 是**半双工顺序时序**，并非全双工同时收发！
  1. `drv8316.c` 调用 `SPI_SendAndReceive(SPI0, 2, w, 2)`：控制器先在 Phase 0 发出 2 字节（16 个 SCLK），再在 Phase 1 发出 2 字节（16 个 SCLK），同一个 CS 有效期内共打出 **32 个时钟**。
  2. `mt6701.c` 调用 `SPI_SendAndReceive(SPI1, 3, 0, 3)`：共打出 **48 个时钟**。
- **对芯片与 CPLD 的破坏性影响**：
  - **DRV8316**：数据手册明确规定，SPI 帧必须严格为 16 个时钟。超过 16 个时钟时，芯片判定帧格式错误，抛弃数据并设置 `IC_STAT.SPI_SCLK_FLT = 1`。
  - **CPLD 逻辑**：`logic/spi_mode_wrap.v` 中的 `rx_shift` 是 32 位的移位寄存器。48 个时钟会直接导致前 16 位有效数据被移出丢失，留在寄存器中的只有尾部的无效电平。
- **整改方案**：
  硬件上 MISO 数据已由 CPLD 包装核 `spi_mode_wrap` 在下沿异步抓取并锁存至 `SPIW_RXDATA` 寄存器。MCU 侧硬 SPI 仅充当时钟发生器，**必须改用 `SPI_Send`**：
  ```c
  // drv8316.c:
  SPI_Send(SPI0, 2, w); // 仅产生 16 个时钟
  // mt6701.c:
  SPI_Send(SPI1, 3, 0); // 仅产生 24 个时钟
  ```

### P0-2: 小端字节序导致 DRV8316 帧头与数据高低字节颠倒
- **根因分析**：
  - `app_io.c` 配置了 `SPI_Init(SPI0, SPI_CTRL_SCLK_DIV16)`，内部使能了 `SPI_CTRL_LITTLE_ENDIAN`（小端模式）。
  - 在小端模式下，当向 SPI 控制器写入 16 位数据 `w` 时，控制器**先移出低 8 位 `w[7:0]`，后移出高 8 位 `w[15:8]`**。
  - `drv8316.c` 中 `make_frame` 的组包方式为：
    ```c
    uint16_t w = (((read ? 1u : 0u) << 15) | ((addr & 0x3F) << 9) | data);
    w |= (parity << 8);
    ```
    这里高 8 位为 `[W, Addr, Parity]`，低 8 位为 `[Data]`。
- **破坏性影响**：
  DRV8316 物理线上先收到 Data 字节，后收到 Command 字节。芯片解码完全错乱，导致奇偶校验错误（`SPI_PARITY` 故障）或意外篡改错误地址的寄存器。
- **整改方案**：
  组包时进行 16 位大小端字节对调（Byte-swap）：
  ```c
  static uint16_t make_frame(int read, uint8_t addr, uint8_t data) {
    uint16_t w = (uint16_t)(((read ? 1u : 0u) << 15) | (((uint16_t)(addr & 0x3Fu)) << 9) | data);
    uint16_t p = (uint16_t)((w >> 9) ^ (w & 0xFFu));
    p ^= (uint16_t)(p >> 4); p ^= (uint16_t)(p >> 2); p ^= (uint16_t)(p >> 1);
    w |= (uint16_t)((p & 1u) << 8);
    // 关键修正：大小端字节倒序，使 Command/Addr 高字节先于 Data 低字节发出
    return (uint16_t)((w << 8) | (w >> 8));
  }
  ```

### P0-3: DRV8316 硬件互锁：INLx 恒高导致模式切换写操作被拒
- **根因分析**：
  设计文档 §3 明确标注：`INLA/B/C -> AVDD（恒高）`。
  根据 TI DRV8316 数据手册 §8.3.1.2（*PWM Mode Configuration*）：
  > **"To change the PWM mode, all INHx and INLx inputs must be held logic LOW before and during the SPI write to the PWM_MODE bits. If any input is HIGH when writing to PWM_MODE, the register write is IGNORED."**
- **破坏性影响**：
  1. DRV8316 上电默认模式是 **6x PWM 模式**（`PWM_MODE = 00b`）。
  2. 若硬件上将 INLA/B/C 硬连到 AVDD，芯片引脚持续检测到高电平。
  3. 执行 `drv8316_init()` 试图写 `CTRL2 = 0x7C`（设置 `PWM_MODE = 10b`，3x 模式）时，**芯片内部逻辑会无条件忽略此寄存器写入**！
  4. 芯片将永久驻留在 6x 模式。在 6x 模式下，INLx=1 意味着三个下桥臂持续导通短路；一旦 INHx 有 PWM 输入，芯片将触发过流保护或直通故障。
- **整改方案**：
  - **PCB 未做**：绝不可将 INLA/B/C 直连 AVDD。至少将其经 10k 下拉电阻接地，或由 MCU 独立引脚/共用使能引脚控制。只有在 SPI 完成 3x 模式配置后，才允许将 INLx 置高。
  - **PCB 已打样**：检查是否能换用出厂默认即为 3x 模式的型号变种，或通过飞线割线解除 INLx 恒高状态。

### P0-4: CCR 浮点转整型无下限界幅导致 100% 满占空比击穿
- **根因分析**：
  在 `src/foc.c` 中：
  ```c
  pwm3ph_set((int32_t)((float)PWM3PH_ARR * 0.5f + v_a * k),
             (int32_t)((float)PWM3PH_ARR * 0.5f + v_b * k),
             (int32_t)((float)PWM3PH_ARR * 0.5f + v_c * k));
  ```
  在 `src/pwm3ph.c` 中：
  ```c
  void pwm3ph_set(int32_t ccr_a, int32_t ccr_b, int32_t ccr_c) {
    GPTIMER0->CCR0 = (uint32_t)ccr_a;
    ...
  }
  ```
- **破坏性影响**：
  若由于浮点精度舍入、电压极限 $V_{max}$ 设定或瞬态过调，导致算出的值小于 0（例如 `-1`）：
  - 强制类型转换为 `(uint32_t)(-1)` 将变成 **`0xFFFFFFFF`（4,294,967,295）**。
  - 定时器 ARR 为 2499。在 PWM1 模式下（CNT < CCR 时为有效电平），CNT 永远小于该 CCR。
  - **该相上桥臂将 100% 永久导通**！对于 2205 云台/动力电机（相电阻通常仅零点几欧姆），母线电压（如 12V）直接加载在绕组上，瞬态电流将高达几十安培，导致驱动芯片过流炸机或电机烧毁。
- **整改方案**：
  在写入 CCR 前强制进行安全饱和限幅：
  ```c
  static inline uint32_t clamp_ccr(int32_t val, uint32_t arr) {
    if (val < 0) return 0;
    if ((uint32_t)val > arr) return arr;
    return (uint32_t)val;
  }
  ```

## 2. 严重级问题详细分析（P1）

### P1-1: 缺少电角度零点偏移（Zero Electric Angle）与方向标定
- **根因分析**：
  `src/foc.c:48` 中计算电角度：
  ```c
  float ang_e = TWO_PI_F * (float)(((uint32_t)s_angle.angle * g_foc.pole_pairs) & 0x3FFFu) / 16384.0f;
  ```
  该式默认磁编码器的 0 度与电机转子 d 轴严格物理对齐。但在实际装配中，绝对值磁铁与定子绕组初始相对角度是随机的，存在固定偏角 $\theta_{zero}$。
- **后果**：
  FOC 电压矢量施加角度偏差一个随机常数。若偏差接近 90°，施加的力矩电压全部变成直轴充磁电流，电机不转且严重发烫；若偏差位于负阻尼半平面，电机会剧烈震颤甚至飞车。
- **整改方案**：
  引入开环标定流程（Voltage Alignment）：
  在初始化阶段强制施加 $V_d = V_{align}, V_q = 0$，延时等待转子吸合至 d 轴，读取此时 MT6701 角度作为 `zero_electric_angle`；后续实时计算时必须扣除该偏置。

---

### P1-2: 上电拉低 `nSLEEP` 导致板载 Buck 停机引发无限复位循环
- **根因分析**：
  - 设计文档 §5 说明 AG32 由 DRV8316 内部集成的 Buck 降压 3.3V 供电。
  - `src/app_io.c:44` 在系统刚启动时调用了 `drv_sleep()`，将 PIN_5（nSLEEP）拉低。
  - DRV8316 上电默认 `CTRL6.BUCK_PS_DIS = 0`。在低功耗休眠下，**Buck 转换器会随 nSLEEP 拉低而关闭或进入睡眠模式**！
- **后果**：
  一旦 Buck 停机，AG32 的 3.3V 供电塌陷，MCU 欠压复位；复位后引脚恢复弱上拉/浮空，Buck 重新上电，MCU 再次启动并执行 `drv_sleep()`，导致系统陷入无限复位脉冲死锁。
- **整改方案**：
  严禁在上电初期拉低 nSLEEP。`app_io_init` 中必须保持 `drv_wake()`，待写入 `CTRL6` 锁定 Buck 常开之后，方可根据需要控制低功耗模式。

---

### P1-3: 定时器中心对称中断双边沿触发导致 40kHz 错误采样
- **根因分析**：
  `src/pwm3ph.c:13` 配置了 `GPTIMER0->CR1 = (0x3u << GPTIMER_CR1_CMS_OFFSET)`（CMS=11b，中心对称模式 3），且未配置 `RCR`（重复计数器，默认 0）。
  在 STM32 / AG32 定时器架构下，CMS=3 模式会在计数器**上溢（波峰）和下溢（波谷）各产生一次更新中断**。
- **后果**：
  标称 20kHz 的 PWM 产生了 **40kHz 的中断（周期仅 25µs）**。
  在低边电阻采样拓扑下，只有波谷时刻（上桥全关、下桥全通）相电流才流经低边采样电阻。在波峰时刻采样只能采到 0 或地线杂波，导致每隔一次采样的电流数据完全失效。
- **整改方案**：
  1. 设置重复计数寄存器 `GPTIMER0->RCR = 1`，使定时器每隔两次溢出（仅下溢）触发一次中断；
  2. 或者在中断服务例程入口处加入计数方向检测：
     ```c
     if (GPTIMER0->CR1 & GPTIMER_CR1_DIR) {
       // 仅在向下计数到达波谷时执行 FOC
     }
     ```

## 3. 警告与优化级问题详细分析（P2）

### P2-1: MT6701 挂载在 DRV8316 AVDD (30mA) 上的过载与倒灌风险
- **风险分析**：
  DRV8316 的 AVDD 为内部模拟 LDO，全温区额定驱动能力仅 **30mA**。DRV8316 片内模拟电路与 VREF 已消耗 10~15mA，MT6701 标称工作电流 12~16mA，叠加后逼近 30mA 极限，极易在动态过程中触发 `AVDD_UV` 报警。
  此外，当驱动器休眠关闭 AVDD 时，MT6701 断电，MCU 的 SPI 引脚仍输出 3.3V，将通过 MT6701 片内 ESD 二极管产生反向倒灌漏电。
- **建议**：MT6701 的 VDD 应直接接入系统的 3.3V 主电源轨（Buck 输出端），不要借用 DRV8316 的 AVDD。

### P2-2: MT6701 5V EEPROM 烧录跳线击穿 MCU 引脚风险
- **风险分析**：
  设计文档中提到在 MT6701 EEPROM 烧录时通过跳线切入 5V。此时 MT6701 的推挽 DO 引脚输出高电平接近 5V，直连 AG32 的 PIN_28（JNTRST）。AG32 管脚并非 5V 耐压，长时间注入高压会导致管脚损坏。
- **建议**：若保留 5V 跳线，需在 DO 串联 1kΩ 限流电阻，或标明烧录时须物理断开 MCU 连接。

### P2-3: 电流采样阻塞轮询但未介入闭环
- **风险分析**：
  `foc_step_isr` 每次都执行 `current_trigger()` 并通过 `ADC_WaitForEoc` 轮询等待 3 个 ADC 转换（耗时约 1.04µs），但计算中并未执行 Clarke/Park 变换与电流 PID 调节，直接将 `s_ib` 赋值给诊断变量。
- **建议**：若当前版本仅验证开环电压力矩模式，可将 ADC 采样移出高频中断或改为 DMA/降频触发，节约宝贵的 CPU 开销。

## 4. 关键代码整改推荐

### 4.1 修复 `src/drv8316.c`
```c
static uint16_t make_frame(int read, uint8_t addr, uint8_t data)
{
  uint16_t w = (uint16_t)(((read ? 1u : 0u) << 15) | (((uint16_t)(addr & 0x3Fu)) << 9) | data);
  uint16_t p = (uint16_t)((w >> 9) ^ (w & 0xFFu));
  p ^= (uint16_t)(p >> 4);
  p ^= (uint16_t)(p >> 2);
  p ^= (uint16_t)(p >> 1);
  w |= (uint16_t)((p & 1u) << 8);
  // P0-2 修复：大小端颠倒，保证控制高字节先行
  return (uint16_t)((w << 8) | (w >> 8));
}

drv_resp_t drv8316_xfer(int read, uint8_t addr, uint8_t data)
{
  drv_resp_t r;
  uint16_t w = make_frame(read, addr, data);

  // P0-1 修复：禁止调用 SPI_SendAndReceive，改用单相 SPI_Send 输出严格 16 个时钟
  SPI_Send(SPI0, 2, w);
  delay_ns(500);

  uint16_t resp = (uint16_t)(SPIW_RXDATA0 & 0xFFFFu);
  r.stat = (uint8_t)(resp >> 8);
  r.data = (uint8_t)(resp & 0xFFu);
  return r;
}
```

### 4.2 修复 `src/mt6701.c`
```c
int mt6701_read(mt6701_sample_t *s)
{
  mt_csn_low();
  delay_ns(150);

  // P0-1 修复：改用 SPI_Send 发送 3 字节 dummy，严格输出 24 个时钟

  delay_ns(150);
  mt_csn_high();
  delay_ns(500);

  uint32_t frame = SPIW_RXDATA1 & 0xFFFFFFu;

  s->mg    = (uint8_t)((frame >> 6) & 0x0Fu);
  s->push  = (uint8_t)((s->mg >> 2) & 1u);
  s->field = (uint8_t)(s->mg & 0x03u);
  s->overspeed = (uint8_t)((s->mg >> 3) & 1u);

  uint8_t rx_crc = (uint8_t)(frame & 0x3Fu);
  uint8_t calc   = mt6701_crc6(frame >> 6);
  s->crc_ok = (rx_crc == calc);
  return s->crc_ok;
}
```

### 4.3 修复 `src/pwm3ph.c`
```c

  GPTIMER0->RCR  = 1;
  GPTIMER0->CR1  = (0x3u << GPTIMER_CR1_CMS_OFFSET) | GPTIMER_CR1_ARPE;
  ...
}

void pwm3ph_set(int32_t ccr_a, int32_t ccr_b, int32_t ccr_c)
{
  // P0-4 修复：强制上下限饱和保护，杜绝 0xFFFFFFFF 致命溢出
  if (ccr_a < 0) ccr_a = 0; else if (ccr_a > (int32_t)PWM3PH_ARR) ccr_a = PWM3PH_ARR;
  if (ccr_b < 0) ccr_b = 0; else if (ccr_b > (int32_t)PWM3PH_ARR) ccr_b = PWM3PH_ARR;
```
