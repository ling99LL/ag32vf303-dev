## 发现并处理的问题

| 编号 | 原问题及影响 | 本轮处理 |
|---|---|---|
| 01 | `mt6701_read()` 在 CRC 失败时也填写 sample；FOC 原来直接传全局 sample，坏角度进入换向 | 使用临时 sample，仅在 CRC 成功时提交角度；累计和连续错误分开统计，连续 8 次异常锁存故障 |
| 02 | 无有效对齐数据、转子未动也可能继续启动；普通角度均值在 0/16383 边界出错 | 电角度域环形均值，32 帧至少 24 帧有效并检查集中度；方向仅接受 ±90°附近窗口，否则拒绝启动 |
| 03 | 标定时未明确拉高 INL，可能无磁场却算出零点 | 对齐显式使能 INL/MOE，退出每个路径都关闭输出；对齐幅度使用 20% 参考调制，实际能否克服摩擦仍需上板确认 |
| 04 | ADC 超时仍读取旧 DATA；无效校准值被静默替换成 2048 | EOC 截止时间 10µs（200MHz 时钟），接口返回成功/失败；校准区间之外拒绝启动，运行超时触发释放，失败时不更新遥测 |
| 05 | SDK `SPI_Send` 无期限等待 DONE，ISR 可能永久停住并保留上次输出 | 项目使用同样的单相传输寄存器顺序，增加 20µs 截止时间和错误返回；接收前检查桥完成状态，避免旧帧伪装新帧 |
| 06 | MT6701 的 CSN 尾保持仍按旧 12.5MHz 注释，150ns 未显式计入桥延迟与 3.125MHz 半周期 | 参考资料 `TL≥0.5*TCLK`，改为等待 500ns 后释放 CSN，覆盖 DEPTH12 的约 120ns 排空延迟和 160ns 半周期 |
| 07 | 主循环看到 FAULT 后自动 stop，故障丢失，后续命令直接重启 | FAULT 锁存；`s/g/n` 只能释放，`z` 检查驱动配置/状态、16 帧编码器、ADC 和 BRK 后才能回 IDLE |
| 08 | 手动模式标志在 stop/fault 时没有统一清除，下一 ISR 仍可能写手动 PWM；`p/N` 可绕过控制状态 | 手动运行属于统一 RUN 状态；离开 RUN 不再覆盖输出；删除静态 PWM/裸 INL 拉高绕过入口，手动幅度也限制在 20% 内 |
| 09 | 动作完成后转入自动 HOLD，持续伺服与已确认的停止释放要求不一致；收尾之后同一 ISR 可能继续下发旧力矩 | 增加 DONE，上报前立即关闭输出并 return；状态值 2 保留但没有主动 HOLD；位置受阻报告故障，不伪装成功 |
| 10 | 停止后再次启动没有一致的 MOE 使能路径；旧比较预装载值可能在重新通电时暴露 | 统一 `pwm3ph_arm/release`，先在输出关闭时锁存中性占空比，再启用；启动不能清除 BRK，只有检查恢复可确认 BRK |
| 11 | `(ticks*1000)` 在约 107 秒溢出；位置和小步长 float 长期累加精度退化 | 时间乘法提升至 64 位；位置使用 64 位，轨迹使用相对起点 Q16 定点；限制单动作最长 1 小时并检查圈数/速度/NaN/Inf |
| 12 | 原开环持续改编码器零偏与方向，再靠“速度乘二”补偿，既污染标定也仍依赖反馈 | 改用 `comm_angle_e` 独立电角度累加器，电角速度=机械速度×极对数，不改标定，支持正反转 |
| 13 | 前台与 ISR 可在多字段动作初始化、模式切换和恢复中互相打断 | 动作 API 使用可嵌套、保存原状态的短中断临界区；慢速恢复检查期间仅停 PWM IRQ；初始化先完成再挂 ISR |
| 14 | 每 100ms 只读一个串口字节；`x/w` 等参数时会吞掉停止命令；自动运行取消逻辑没有兑现 | 主循环按真实 mcycle 时间轮询，每轮最多处理 32 字节；停止优先于参数处理，参数 1 秒超时；取消标志落实 |
| 15 | DRV 故障主要只为显示，硬件 BRK 清除策略可让故障失去锁存 | 每拍检查 BRK 并锁存故障，后台检查 IC_STAT；启动和恢复均检查状态，启动健康失败保留串口诊断 |
| 16 | 原 Quartus 包装脚本不检查失败，可能复用旧 summary/网表仍打印 done | 执行前移除对应旧报告；检查每步新报告、ADC×3 分区与网表、时序；记录输入/网表哈希，Supra 拒用失配输入并检查新产物与 setup/hold |
| 17 | `foc_last_iq()` 实际是一相 ADC 值；“2V/20%”注释掩盖了真实缩放方式 | 移除伪 iq 与未使用的电流环增益字段，明确当前为电压调制模式；Q12 是归一化指令，电流为零点校正 ADC LSB |
| 18 | 上位机手动档最高 100%；重连时旧线程读取可变 self.ser；断开非手动运动不发 stop | 配套 v2 档位 5/10/15/20%，协议匹配后允许控制；读线程绑定各自端口与退出事件；断开尝试发送 s，配置写超时 |
| 19 | README/代码注释混用不同 SPI 频率、采样沿、自动保持与调参历史，文件索引过时 | 当前 README/索引重写，旧 README 完整归档；SPI0/1 均 3.125MHz，MT 桥实际 CAP_RISE=0，PIN_28 当前用于 INL |

20% 是相对调制参考的上限，不等于电功率 20%、实际 0.4V 或受控电流。实际相电压随 VM 变化；本轮没有加入 Vbus 测量或电流反馈。

## 尚未完成的物理或产品验收

1. 新固件与新位流没有烧录或上板验证。需要重新确认对齐成功率、传感器方向、正反转、停止/故障释放、恢复后待命和重启。对齐幅度、直接开环及位置轨迹改变后，旧调参日志不再作为通过依据。
2. 未测真实 ISR 负载/抖动、SPI/CSN 波形、电流与发热。截止时间及延时根据 200MHz/100MHz 配置推算，不能当作波形实测。
3. 27 条 Supra 警告由 3 个 ADC 自动放置提示和 24 个时钟使能跨域提示组成；本轮没有修改 SDK 时钟树。工具零错误不等于零警告签核，应结合 99.2% 时序覆盖继续评估。
4. 通信仍是字符诊断协议。ADR 中的完整帧协议、心跳超时保护、宿主命令应答/序号和具体手感模式尚未实现；手动模式的 30 秒超时不能代替全局通信心跳。
5. 当前是调制控制，DRV 的硬件保护仍然承担驱动故障切断；没有闭环电流控制或经过验证的电机电流上限。
6. PIN_28 与 JNTRST 复用，若探针实线驱动 nTRST 低，运动时 INL 拉高仍可能电气冲突；需核对实际电缆，不能笼统声称“调试零影响”。
7. `docs/basic-motion-acceptance.md` 中 3/6/15rpm 正反向各连续 5 圈的六项均未执行。开环 DONE 只代表电矢量推进时长结束，机械实际圈数需编码器累计和独立观察确认；现有跳变钳位遥测也需实测评估。

## 构建中遇到的环境问题

旧脚本“失败也 done、复用旧文件”是工程本身问题，已替换。新包装适配时，Quartus 的导出宏名实际包括 `alta_adc_1/2`，检查按三实例处理；Windows PowerShell 的 `Get-FileHash` 可用性及原生 stderr 被当作终止错误的问题，改为 .NET SHA256 和独立进程捕获。最终包装命令均通过。保留对历史 fast-fail `0xC0000409` 的受限兼容：必须同时有新成功报告，不能只忽略退出码。
