# FOC2205 firmware 20261017.25 release note

- Version: `fw=20261017.25`
- Git tag: `foc2205-fw-20261017.25`
- Status: hardware validated
- Closed-loop conclusion: **PASS** (automatic telemetry/GUI validation)

## Highlights

- SPIN speed is continuously selectable from 3 to 60 rpm with `rpm <3-60>`;
  the legacy `V1..V4` gears remain compatible.
- The panel replaces the speed dropdown with a slider and keeps
  3/6/15/60 rpm shortcut buttons.
- A/B/C phase currents are displayed directly below the encoder. The compact
  `$T` telemetry now appends `ia,ib,ic,adcok`, while 12/13-field frames remain
  parseable.
- A full-width emergency-stop button and `Esc` send `estop`, which calls
  `motion_stop()` immediately. This is distinct from `s`, which uses the
  bounded SPIN deceleration path.
- Long panel pages now scroll, so the SPIN controls remain reachable on a
  smaller/high-DPI desktop.

## Validation

- Host regression: `ALL CONTROL REGRESSIONS PASSED`; 9 Python protocol tests
  passed; continuous `rpm` and immediate `estop` parser paths passed.
- Both PlatformIO environments built successfully:
  `foc2205` and `foc2205_bringup`.
- `foc2205_bringup -t upload` wrote and verified the MCU image.
- Hidden-Tk real COM26 smoke:
  - closed-loop speed changed from 6.00 to 12.00 rpm while running;
  - after the 12 rpm step settled for 2.5 s, measured means were
    6.57 and 11.37 rpm;
  - the initial un-settled 12 rpm window reached a 13.32 rpm mean in one
    repeated run, so the final test deliberately measures steady state;
  - ISR stayed at 20,005 Hz;
  - A/B/C current display updated from high-rate `$T`;
  - `estop` changed the drive to `out=0` in 0.80 s.
- Final board state:
  `fw=20261017.25, ready=1, st=0, out=0, fault=''`, calibrated
  `calst=7, calpk=440`, `hz=20005`.

## Boundaries

- Automatic telemetry and GUI evidence establish closed-loop control and
  release behavior; they do not replace a human assessment of m1/m2/m3/m4
  feel or mechanical noise.
- The first-CPLD-access hang remains a known unresolved board bring-up issue.
  This release was recovered with the documented CPLD rewrite plus WDOG reset
  sequence; no root-cause claim is made.
