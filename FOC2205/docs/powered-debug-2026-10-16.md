# FOC2205 通电低速调试记录

2026-10-16，COM26 / 115200 8N1，AGM CMSIS-DAP。用户确认全部供电接通，并在首次访问 CPLD 再次卡住后执行了整板断电重上电。没有进行 6/15 rpm、闭环或五圈验收。

## 结果与当前状态

- 修复 SPI 超时误复位后，DRV 配置轮询稳定，MT6701 CRC 错误为 0；ADC 零点约 A=2069、B=2063、C=2063，采样 ISR 约 20009 Hz。
- 2% 校准未达到位移判据；保持 90 电角度/秒（7 极对约 2.14 机械 rpm）的扫角，将调制提高到 3% 后到达 `calst=7,aligned=1`，随后释放输出时出现 `driver break`。
- 显式检查恢复后，完成 3 rpm 指令的正、反向短动作，每次约 3 秒，调制 `293/8192`，约 3.58%。两次均在发送停止、输出关闭后出现 BRK 锁存。
- 最后发送停止、读取故障、执行检查恢复，再持续观察 5 秒：`st=0,out=0,brk=0,drvok=1,encok=1,adcok=1,cal=1,crc=0`，角度保持 12010。电机处于无输出待命，不会自动续跑。

| 动作 | 编码器最终净位移 | 输出开启采样间平均速度 | 结论 |
|---|---:|---:|---|
| 正向约 3 秒 | +61.55° | +3.42 rpm | 有转动，停止后 BRK；未通过稳定运动验收 |
| 反向约 3 秒 | -42.50° | -2.45 rpm | 有转动，启动短暂反抽，停止后 BRK；未通过 |

速度来自相邻 UART 状态帧的编码器差分，不是示波器或独立转速计。约 0.1 秒采样区间的正向最大差分约 13.26 rpm、反向最小约 -8.43 rpm，说明启动/低速跟随仍有瞬态；3 rpm 是指令值，不能称为恒定实测转速。净位移包括起停段。反向最初仍向正方向移动约 7.5°。未继续提高幅度或转速。

## 本轮修复

### SPI 完成与超时检查竞争

`app_spi_send()` 在前台读到 DONE=0 后可能被 PWM ISR 抢占；ISR 返回时 SPI 已结束，原代码却直接按经过时间复位 SPI。实测失效后的 SPI0 CTRL 为 `0x00008202`，PHASE_CTRL/DATA 为 0；复位恢复成 DIV8、大端，后续字节交换后的读命令访问地址零，各寄存器都表现为 `0x08`。

修复在超时分支重新检查 DONE，并在真正超时复位后恢复 divider/endian/WP 配置。没有屏蔽驱动配置保护，也没有增加跨串口打印的中断屏蔽。修复后的驱动轮询及运动期间配置读回保持 CTRL2=7C、CTRL6=11。

### CPLD AHB/APB 桥

原桥使用单拍完成脉冲；本轮改为 request/ack toggle、双触发同步和保持响应，写数据按 AHB 数据阶段保存。ModelSim 对新桥的 401 次事务、APB 等待、200/10 MHz SYS 时钟切换仿真通过；同一激励对原桥出现重复事务/错误数据并超时。

Quartus 启用 `OPTIMIZE_HOLD_TIMING ALL PATHS` 后时序通过，保留宏分区护栏与 ADC×3。Supra 零错误，SYS/BUS 最差 setup slack 为 0.686/2.358 ns。24252 字节位流已烧录并校验，SHA256：

`2CE00FDD8CFBADF0D870F68BC76EF85CB6C72D9CFFF2B16F2885D3EADA7100F5`

新桥上有运行态 system-bus 读取成功证据，但烧录复位后的首次 CPLD 访问仍多次卡住。整板断电后恢复，不能宣称复位/冷启动可靠性已通过。

# 第二轮（同日深夜）：BRK 误报、反向起步反抽修复与六组合五圈验收

2026-10-16 深夜，COM26 / 115200 8N1。在上一轮“停止即 BRK、反向起步反抽”两项定位基础上修复根因，并首次执行 [基础运动验收](basic-motion-acceptance.md) 的六个开环组合。全部为本机串口脚本实测，无示波器、无电流探头、无独立转速计。

## 结论摘要

- 六个组合（3/6/15 rpm × 正/反向）各 5 圈**单次通过**：方向正确、编码器累计机械角全程单调（无一帧反向步进）、无失步/中止、停止后释放且**不再锁存 BRK**。
- 实测圈数 4.979～4.998 圈（指令 5 圈），平均转速与指令一致（3.00 / 5.99 / 14.98 rpm）。差值 0.02%～0.4% 与起步斜坡、采样窗口边界同量级，不是失步。
- 仍未验证：实际相电流/相电压波形、功率级温升、带载手感、闭环。BRK 硬件通道当时也未做注入验证，已在第三轮补上（见文末《第三轮》）。

## 修复 1：正常停止被误判为 driver break

- **现象（可复现）**：`!` MOE-only 自检（INL 低、驱动 Hi-Z、电机未通电）打印 `MOE-only cycle: INL=0 BRK=1 SR=0000001e/0000001e/0000009e`。三段 SR 分别是“释放前 / 拉低 INL 后 / 清 MOE 后”，只有最后一段多出 bit7（BIF）。同时 `GPIO4=0x1e` 表明 PIN_22/nFAULT 一直为高，DRV 也没有故障（`IC_STAT=0x08 STAT1=0x00`）。
- **根因**：本片 GPTIMER0 在 **MOE 1→0 的那次写入本身就会置位 BIF**。于是每次正常释放（`pwm3ph_outputs(0)`）都被 `pwm3ph_faulted()` 判成 "driver break"，并在 ISR 中锁存为 MOTION_FAULT。上电后 MOE 从未使能时 BIF 不会置位，所以待机状态看不出问题。
- **修复**（`src/pwm3ph.c`）：把“真实事件”放进软件。写 MOE 前先采样 BIF，已置位则锁存到 `s_break_latch`；随后在 `s_release_window` 窗口内清掉本次自己写入造成的标志，避免 ISR 在两次写之间抢到假标志。运行中（MOE=1）的硬件断路仍走原路径锁存，安全语义不变。
- **验证**：同一 `!` 自检变为 `BRK=0 SR=0000001e/0000001e/0000001e`；校准完成释放、正反向停止，以及一次**运行中途** `s` 停止（6 rpm 试跑被脚本提前结束）都没有再锁存 BRK。

## 修复 2：反向起步反抽

- **现象**：反向指令起步瞬间转子先向**正**方向走约 8.9°（≈62° 电角度）再反向跟随；正向因方向相同只表现为“起步偏快”（首帧 +484 counts）。
- **根因**（`src/motion.c` `start_fixed`）：逆 Park 把电压矢量放在换向角**前方 90°**。开环起步用 `s_angle = encoder_elec()`，等于把矢量直接摆在转子前方 90°，转子先被拉向该方向（+），之后扫角方向才接管。
- **修复**：开环起步把矢量落在转子上（`s_angle = wrap(θ - 90°)`），力矩从 0 开始、随扫角方向建立；力矩保持（TORQUE）模式保持原“矢量在前 90°”的行为，因为那正是它从静止施力的方式。
- **验证**：反向首帧步进变为 −24/−26/−124 counts（全部负向），100 s 反向验收 873 步无一正向；正向起步由首帧 +484 counts 变为 6→21→39 counts 的平缓斜坡。

# 第三轮（同日）：nFAULT 硬件断路通道验证

2026-10-16 深夜，COM26 / 115200 8N1。目标：验证“nFAULT 真被拉低时，硬件是否立即清 MOE 并置位 `SR.BIF`”，并把固件据此锁存 `MOTION_FAULT("driver break")`、再显式恢复的整条链路走通。全部为调试探针 + 串口实测，无示波器。本轮**不改固件、不重烧**。

## 方法：用 DRV8316C 自身故障产生 nFAULT

原计划把 PIN_22/nFAULT 对地短接，但**本板排针只引出 PIN_24～27，PIN_22 未引出**，无法从外部拉低。改为让 DRV8316C 自己产生一次真实故障：

- `CTRL3 = 0x44` 清 `SPI_FLT_REP`（复位默认 0x46 = 关闭 SPI 故障上报），使 SPI 故障上报到 nFAULT 引脚。
- 发一个**只有 8 个 SCLK 的帧**（`PHASE_CTRL=0x100`，字节数 1），违反“事务必须满 16 SCLK 才有效” → `STAT2.SPI_SCLK_FLT` + `IC_STAT.SPI_FLT/FAULT` → DRV 拉低 nFAULT。
- `CTRL2.CLR_FLT`（写 `0x7D09`）清除。

这是驱动自身真实产生的故障响应，不是外部注入的引脚电平。**注意**：越界寄存器地址（读/写 `0x3F`）在本片 DRV8316C 上**不会**被标记（`nfault_probe.tcl` 对比三种条件），只有帧长错误有效。

## 前置确认

- **调试器侧 SPI 帧与固件一致**（`nfault_sanity.tcl`）：IC_STAT=0x08、CTRL2=0x7C、CTRL3=0x46，与固件 `f` 命令读回一致。
- **`halt` 真冻结内核**（`halt_check.tcl`）：PC 停在 `0x800003c0` 不动，而 GPTIMER0 CNT 持续计数（0x57d→0x2d5→0x18d）。因此 halt 期间的 MOE/BIF 变化是纯硬件行为。

## 硬件通道证据（核心）

内核 **halted**、MOE 已 arm（INL 保持低 → 驱动 Hi-Z、无扭矩）时注入 8-clock 帧：

```
clean     GPIO4=0x1E nFAULT_pin=1 MOE=0 BIF=0 IC_STAT=0x08 STAT2=0x80
MOE=1     GPIO4=0x1E nFAULT_pin=1 MOE=1 BIF=0 IC_STAT=0x08 STAT2=0x80
INJECTED  GPIO4=0x1C nFAULT_pin=0 MOE=0 BIF=1 IC_STAT=0x29 STAT2=0x82
MOE retry GPIO4=0x1C nFAULT_pin=0 MOE=0 BIF=1 IC_STAT=0x29 STAT2=0x82
```

- `GPIO4` bit1 = PIN_22：`1→0`，DRV 真的把 nFAULT 拉低。
- `MOE`：`1→0`、`BIF`：`0→1`，均在**无软件运行**时发生，是 GPTIMER0 断路输入的直接硬件响应。
- nFAULT 仍低时重试 arm MOE，读回仍为 `MOE=0`（硬件门控有效）。
- `IC_STAT=0x29`（NPOR|SPI_FLT|FAULT）、`STAT2=0x82`（SPI_SCLK_FLT + 正常位）。

## 固件反应与恢复

`resume` 后立即：

```
MOVE ABORT: driver break (err=0 raw, vel=0 raw/s, vq=0, t=100000 ms)
#FOC,...,drv=0x29,...,st=3,...,brk=1,out=0,fault=driver break
```

`z` → `recovered: idle, outputs off`；随后 `st=0 out=0 brk=0 drv=0x08`。`nfault_restore.tcl` 把 CTRL3 还原为 `0x46` 并清 DRV 故障（`IC_STAT=0x08 STAT2=0x80`）。

## 注入后回归

重新校准（`calst=7, aligned=1`）后跑 3 rpm 正向 5 圈：**+4.990 圈、3.00 rpm、反向步进 0、glitch 0、停止后 st=0 out=0 brk=0**（`225202-nfault-after-3rpm-fwd.txt`）。第一次 `a` 曾报 `calibration no movement`，`z` 后重试通过——与首轮 2%→3% 的历史波动一致。

## 本轮复跑的补充

第三轮首次收尾时，板子实际停在 `driver break`（`st=3 brk=1 drv=0x29`），那份 end-to-end 日志在 `?` 处中断，恢复步骤未落盘。本轮先发 `z` 恢复至待命，再完整复跑 `nfault_cycle.py`：inject → resume（`MOVE ABORT`）→ `?`（`st=3 drv=0x29 brk=1`）→ `f`（`IC_STAT=0x29 STAT2=0x82`）→ `z`（`recovered`）→ `?`（`st=0 drv=0x08`）→ restore（CTRL3=0x46）全程一次通过，日志 `225820-nfault-cycle.txt`。

## 跳闸事件：`current ADC threshold`

`231527` 那次在第 1 圈 **t=428 ms** 中止：

```
MOVE ABORT: current ADC threshold (err=-2 raw, vel=-76 raw/s, vq=0, t=428 ms)
#FOC,… ia=-2 ib=-1 ic=1 … st=3 … brk=0 … fault=current ADC threshold
```

- 判据是 `src/foc.c` 的 `CURRENT_TRIP_LSB 200`：任一相瞬时 |i|>200 LSB 就跳闸，**没有连续样本计数**，一个坏样本即可触发（`adce=0`、`encok=1`、`drv=0x08`，其它诊断都正常）。
- **量纲换算**（本文档首次给出）：DRV8316C `CTRL5=0x02` → `CSA_GAIN=10b` = **0.6 V/A**（手册 `docs/drv8316_text.txt` 第 898–901 行）；ADC 为 12 位、0–3.3 V、零点 ≈2048 LSB（`current_init()` 的 1500–2600 判据）。故 **1 LSB ≈ 1.34 mA**，跳闸线 200 LSB ≈ **269 mA**。该换算未用标准电流源标定，只作量级参考。
- 10 Hz 采样看到的运动电流（全部通过圈）：峰值多在 25–66 LSB（≈34–89 mA），但 `231333` 那圈在**动作开始约 320 ms** 采到一次孤立的 `ia=-151 LSB`（≈203 mA，跳闸线的 75%），前后两个样本只有 −2/−1；`231527` 跳闸那次也发生在动作开始 428 ms。**离群样本集中在动作起始约 0.5 s 内**（调制从 0 阶跃到 ~200 的窗口），符合“换向/采样瞬间的孤立尖峰”，但本轮数据不足以判定是真实 di/dt 冲击还是采样通路毛刺。
- 同一时刻还出现一次 **约 433 raw（≈9.5° 机械角）的原始角回跳**：相邻两个 115 ms 采样帧 `ang` 由 8901 变成 8468（正常 3 rpm 应前进约 94 raw），固件的跳变计数器 `j` 由 `1/2` 变为 `2/2`（`update_position()` 的单拍步进被钳位计数）。
- 无法据此区分“真实瞬时过流（换向/电流环瞬态）”与“ADC 读数离群值（CPLD 桥/采样通路毛刺）”。可注意的旁证：校准全程（3% 调制扫角）`calpk` 只有 4 LSB，而闭环运动时的读数能到 50 LSB，离群值到 200 的余量只有约 4 倍。

**未做**：没有改固件去加“连续 N 拍超阈”或峰值捕获遥测；没有测量相电流波形，因此不能宣称电流环/过流保护已经过验证。跳闸后 `z` 恢复至待命，未影响后续 8 圈。

## 起步跳闸归因：与力度档无关，与起始电角度有关

20%/25% 档最初 5 次尝试全部在起步跳闸（时间集中在 106–122 ms），表面上像"力度越高越容易跳"；两个对照实验推翻了该解释：

1. **5% 档从同一位置起步也跳**：把 `vq_max` 设回 410，从当时停留位置 ang≈7371 发 `r`，**109 ms 跳闸**（`err=-3, vel=591, vq=0`）。
2. **换位置后 20%/25% 一次通过**：`jog.py` 用 12% 静止矢量把转子点动到 ang=12202（电角度约 +23°），`z` 恢复后 20% 档 +0.991 圈通过，25% 档 +0.993 圈通过。

- 从 ang≈7370–7386 窗口起步的 8 次尝试（5%×1、20%×4、25%×3）**全部在起步跳闸**；通过的各圈起始角都不在该窗口。窗口宽度未测量（`.6` 镜像上 15% 档起始角按上一圈终点推算约 7421，若准确则窗口窄于 50 raw）。
- 跳闸时刻的指令 vq 只有 ~200（2.4%），远低于任何档位上限，**不是限幅饱和引起的真实过流**。5% 档跳闸帧 `ia=-106, ib=13, ic=9`：单相尖峰、其余两相接近零、三相和不满足基尔霍夫；20% 档跳闸前一帧 `ib=-50`。与第四轮"起步 0.5 s 内孤立尖峰"是同一现象，本轮把触发条件缩小到"从特定起始电角度起步"。
- 点动（12% 矢量、+4830 raw）触发过一次 `encoder invalid/field`（MT6701 磁场状态位 `mg&0x0b` 瞬时异常），恢复后正常；作为独立现象记录。
- 机理仍未定：可能是特定电角度下 SVM 占空比组合在 ADC 采样瞬间（PWM 谷点）产生的 CSA 共模假读数，也可能是真实换向瞬态。需要示波器看相电流/CSA 输出，或给 `foc.c` 加"连续 N 拍超阈 + 峰值捕获"遥测才能区分。
