# FOC2205

基于 **AG32VF303KCU6（QFN32）+ MT6701QT-STD + DRV8316C** 的 2205 电机力反馈旋钮驱动工程。与工作区其他旋钮工程独立。电机按 7 极对数配置。

2026-10-16 完成代码排查、控制层重构和测试文件整理。变更、构建结果及待验证事项见 [本轮排查报告](docs/refactor-audit-2026-10-16.md)。随后完成驱动未供电条件下的烧录与 COM26 联调，修复外设时钟翻倍，详见 [未供电联调记录](docs/unpowered-debug-2026-10-16.md)。此前调参和上板叙述保存在 [历史 README](experiments/notes/README-before-refactor-2026-10-16.md)，历史结果不能代表本轮固件实测。

## 当前实现

2026-10-16 通电调试：修复 SPI 超时误复位后，又定位并修复两处运动缺陷——本片 GPTIMER 的 MOE 1→0 写入会自置 BIF（正常停止被误判为 driver break），以及开环起步把电压矢量放在转子前方 90°（反向起步反抽）。修复后 [基础运动验收](docs/basic-motion-acceptance.md) 的 3/6/15 rpm 正反向各 5 圈六个组合各通过一次。随后用 DRV8316C 自身 SPI 故障（8-clock 帧）产生**真实 nFAULT**，在核心 halted 条件下确认硬件立即清 MOE、置位 `SR.BIF`，固件据此锁存 `driver break` 并可显式恢复（`PIN_22` 未引出排针，故用驱动自故障而非外部拉低）。闭环（位置伺服 `r`/`R`）首轮在 3 rpm 下 10 个单圈动作通过、1 次 `current ADC threshold` 过流跳闸中止；跳闸是真实过流还是采样离群值尚未定性，重复性、6/15 rpm、连续多圈和波形仍未验证。当前实测结果、镜像差异和未解决项见 [通电低速调试记录](docs/powered-debug-2026-10-16.md)。

2026-10-17 过流判别与电流环首轮：跳闸判据改为连续 3 拍超阈（`CURRENT_TRIP_LSB=200`≈269 mA，1 LSB≈1.34 mA），孤立单拍计 glitch 并冻结 8 拍快照（`F` 读取并清除）；新增基于实测 id/iq 的电流环 PI（`l` 开关、`K`/`I` 档位），真实断电重上电后 `fw=20261017.1` 运行正常。决定性实验在 10-16 记录的坏窗口（ang≈7370–7386，原 109 ms 单拍跳闸处）完成：电压模式 1 圈 `MOVE DONE`（998/1000），19 次超阈全部孤立（maxrun=1）不跳闸；电流环 ON 同起点 1 圈同样完成（maxrun=1），峰值 `|vq|` 193 vs 236、速度抖动峰值 10629 vs 17507——坏窗口原跳闸定性为孤立采样毛刺；当日另捕捉到真实 `current ADC threshold C n=3` 跳闸一次，判别机制双向有效。细节、日志与复现命令见 [10-17 通电记录](docs/powered-debug-2026-10-17.md)。

2026-10-17 深夜无人值守闭环平滑扫描（两轮）：hybrid 关闭下完成速度×力度基础矩阵 18 步与候选配置确认/重复性全 DONE（0.10 圈/秒最平 cv 18–27%），并完成五连圈验收——**运动环 kp 2→8（`k`×2）为后半程最大单项收益**：0.05–0.25 圈/秒巡航 cv 由 31/21/35% 降到 10.2/7.4/3.6%、残差收紧到 ±32–51 raw（0.05–0.25 档 29/30 通过）；适用范围下限 0.05 圈/秒（0.02 档 kp=8 双向真实跳闸）。0.50 档（30 rpm）起步 ~25–40% 安全中止（MT6701 场状态 / 起步真实过流，kp 与力度均不能消除），不建议常规使用；24 圈 soak（0.10/2048）零漂移零跳闸。**关键发现：混合换向开启（开机默认）会让控制 ISR 由 20 kHz 掉到 ~12 kHz、动作真实时长 ×1.67**，此前"变慢/抖动"判读据此更正；电流环保持默认 K=8/I=100。推荐平滑配置（运行时设定、重启不保留）：`y`(hyb=0) + `j`→kd=60/1000 + `q`→ang_filt=1/256 + `k`×2→kp=8（仅 ≥0.05 圈/秒档）；力度上限与失败模式明细见记录。细节见 [闭环平滑扫描记录](docs/smoothness-2026-10-17.md)。

2026-10-17 `.11` 默认配置推进：`MOTION_HYBRID_DEFAULT` 改为 0，开机即为 `hyb=0`，避免重新上电后回到 20 kHz→12 kHz 的 hybrid 路径；`y` 仍可手动开启。实机 `fw=20261017.11` 在 3 rpm 默认闭环下正反向单圈各通过（+0.993 / -0.984 圈，20.1 / 19.9 s，`hz=20007`，无编码器 glitch）。随后补做开环六组合重复性，3/6/15 rpm 正反向各 5 圈全部通过：实际 4.973-5.000 圈、平均 3.00/6.00/14.98 rpm、零反向步进、零 glitch，结束后均 `st=0 out=0 brk=0`。详见 [开环重复性记录](docs/openloop-repeat-2026-10-17.md)。
2026-10-17 `.12` 位置轨迹加减速：针对 0.50 档起步失败和 0.25 档间歇跳闸，位置动作从“首拍直接给全速步进”改为 0.75 圈/秒² 的梯形加减速，并保留末端精确补偿。`fw=20261017.12` 实测：0.25/1536 的 5×r+5×R 共 10/10 DONE、无跳闸；0.50/1013 与 0.50/768 各 10/10 DONE；补充 0.50/1013/1536/2048 共 6/6 DONE，无 encoder invalid/field。高力度 0.50 仍 cv 51–62%，推荐 0.50 以 1013 为主、1536/2048 仅作力度余量。详见 [位置轨迹加减速记录](docs/position-accel-2026-10-17.md)。

- 电压调制模式：编码器换向、位置轨迹、混合换向、独立电角度开环、定时 q 轴指令和有超时的手动三相诊断。
- 显式 `foc2205_bringup` 环境开机只做驱动/编码器/ADC 自检，**功率输出关闭、不自动移动转子**。上位机“开始慢速校准”或串口 `a` 才会启动 3% 调制的可取消电角度校准；完成后自动释放输出。`A`/`s` 可取消。默认 `foc2205` 为禁用 CPLD 访问与采样 ISR 的恢复镜像。
- 停止、动作完成、故障均关闭功率输出。故障保持锁存，`z` 检查通过后只回待命，不自动续跑。启动标定失败保留查询通信，需处理原因后重启。
- 三相电流默认仅作 ADC 遥测；软件过流保护为"连续 3 拍超阈才跳闸"的计数判别（孤立毛刺计入 glitch 并保留峰值/快照，`F` 读取），电流环 PI 为可选开关（`l`，开机默认关）。仍无母线电压测量或通信心跳。`vq` 为按 `v_limit_q=8192` 归一化的调制指令，**不能据此宣称实际相电压、力矩或电流已受控**。
- 位置轨迹使用相对起点的 64 位定点累加，位置累计使用 64 位；受阻或超时会故障释放，不把未到位伪装成完成。
- **无限旋转 SPIN**：`p`/`P` 启动正/反向连续旋转，`#0/#1` 选择闭环（位置+电流环）/开环（定压矢量）模式，`V1..V4` 选择 0.05/0.10/0.25/1.00 圈/秒（3/6/15/60 rpm），`W1..W8` 选择力度上限。闭环最高 80%，开环因无电流限幅最高 40%；bring-up 镜像的全局 `MOTION_POWER_PCT_MAX` 仍为 25%（源码默认 20%）。闭环启动时强制应用实测平滑预设（hybrid=0、kp=8、kd=60/1000、V1–V3 角滤波 1/256、V4 角滤波 1/64、电流环 ON）；开环关闭电流环，使用固定电压矢量。`s` 以 0.75 圈/秒² 限速减速后释放；主机 1 秒无任何命令时由控制 ISR 自动减速并释放。状态帧在 SPIN 运行期间报 `mode=2`，`open=0/1` 标识模式，`pct` 为力度上限。`fw=20261017.10` 实测：闭环 V1–V3 24/24、V4 8/8；开环 V1/V2×20/40% 8/8、V4 20/40% 4/4；闭环回归 2/2；失联 3.5 s 内减速释放 PASS。60 rpm/60% 开环反向曾触发 DRV OCP，因此开环固定 40% 上限；闭环仍可 80%。校准调制提高到 5%，用于自动脱离端位/静摩擦区；WDOG 系统复位可重新加载 CPLD，后续不再需要手动断电。位置闭环 force8 8/8 DONE。MT6701 场/超速状态位改为 CRC 有效时继续使用角度、持续约 100 ms 才跳闸。完整证据见 [SPIN 验收记录](docs/spin-acceptance-2026-10-17.md)。

## 构建

从本目录运行 PowerShell：

```powershell
$pio = 'C:/Users/Administrator/.platformio/penv/Scripts/pio.exe'
& $pio run -e foc2205 -t prelogic
cmd /c logic\build_steps.bat
cmd /c logic\run_supra.bat
& $pio run -e foc2205 -t buildlogic
& $pio run -e foc2205 -t clean
& $pio run -e foc2205
python experiments/tests/run_tests.py
```

Quartus 13 路径为 `C:/altera/13.0sp1/quartus/bin64`。包装脚本保留硬宏分区扫描及 `PARALLEL_SYNTHESIS OFF`，逐步检查新生成的 summary、三路 ADC 网表和 SHA256；已知 `0xC0000409` 退出只有在新报告验证通过时才允许继续。Supra 校验输入哈希并要求新位流及零错误摘要。`buildlogic` 在自定义 `logic_dir` 流程中只是已有位流的依赖别名，本轮输出为 up to date；它不执行独立 CRC 校验，也不能代替 Quartus/Supra。

仅修改 C 时不需要重建 CPLD。2026-10-16 已实际烧录 logic 和固件并通过字节校验。后续上板时，logic 与固件分别用 `-t logic`、`-t upload`，完成后按实际探针连接复位运行。压缩位流保持 `logic_compress=true`，QFN32 器件保持 `AGRV2KQ32`。工具路径和串口号按本机环境核对。

### SWD 烧录（默认）

正常固件升级直接走 CMSIS-DAP v2 + OpenOCD 的 SWD，不需要 BOOT0 跳线或串口 ROM loader：

```powershell
& $pio run -e foc2205_bringup -t upload
& .\tools\reset_run.bat
```

2026-10-17 实测 DPIDR `0x2ba01477`、10 MHz，SWD 擦除/写入/校验通过（`0x80000000`，45,284 字节）。`-t upload` 末尾会 `reset halt`，用 `tools/reset_run.bat` 恢复运行。**注意**：本板仍存在"复位后偶发首次访问 CPLD 卡死"（CPU 运行、SWD 拒绝 halt、COM26 无输出），唯一可靠恢复是真实断电重上电；这不是串口烧录问题，串口也不能替代该电源循环。

### 串口烧录（仅 ROM loader 兜底）

只有芯片已经处于 ROM UART loader、且 SWD 不可用时，才需要绕过 OpenOCD 通过 COM26 烧录：

```powershell
$env:AGM_PIO_UPLOAD_PROTOCOL = 'serial'
& $pio run -e foc2205 -t upload -p COM26
```

该路径会调用 SDK 的 `agrv32flash`，执行设备识别、擦除、写入和校验。2026-10-16 实测 `COM26 @460800 8E1` 成功，识别 `0x40200001`，固件校验通过并自动复位。日志中的 `Checking logic configuration at 0x80034000` 只校验已有 CPLD 位流，不会重写 CPLD；CPLD 仍需单独使用 `-t logic` 或生产 batch 烧录。复位后安全镜像报告 `stage=90`、`out=0`，没有启动校准或电机动作。

2026-10-17 补充：本机 PIO 的 460800 自定义 booter 初始化失败时，可改用 `agrv32flash -b 57600` 直连，且必须显式给地址。**MCU 的 `-w` 会擦除全片 Flash，因此必须最后写 CPLD**：先 `-S 0x80000000 -w foc2205.bin`，再 `-S 0x80034000 -l logic\foc2205.bin`。若先 `-l` 再 `-w`，CPLD 位流会被静默擦掉；漏掉 `-S 0x80034000` 时 `-l` 会写到错误地址。`-l -v` 会执行写入校验；不要用 `-K 0X80034000 -M foc2205.bin` 复核，该检查把原始文件与“0x1100 解压头 + 压缩位流”的 Flash 布局直接比较，会报假不匹配。正确复核方式是回读 `0x80034000:28604`，确认 `+0x1100` 起的 24,252 B 与 `foc2205.bin` 一致。`tools/uart_flash_all.bat` 已按正确顺序和地址修正。

2026-10-17 `nRST` 实测：DAPLink `nRESET` 已接到 AGM32 `nRST`（PIN_4），OpenOCD 可以触发 SRST/DAP 复位，但复位后 ROM/CPLD 仍可能不恢复、COM26 无输出；因此 `nRST` 不能替代 CPLD 重载或冷上电。可复用的 SWD 恢复方式是在**同一个 OpenOCD 会话**内执行 `NDM reset → arp_examine → agrv write_fpga_config + MCU write/verify → NDM reset → resume`。本机 10 MHz SWD 偶发写 Flash 超时，降到 5 MHz 后稳定。

## 串口控制

UART0，115200 8N1；引脚 PIN_20=TX、PIN_21=RX。`python tools/foc_panel.py` 打开协议 v2 面板，需要 `pyserial` 和 `tkinter`。面板要求 `proto=2,diag=1` 诊断扩展，需配套固件。面板含就绪门控、故障原因、数据有效性、2 秒通信超时、CSV 自动记录与导出，以及 SPIN 的方向/三档速度/10–80% 力度控制和实时 rpm 显示；普通手动不自动保活，SPIN 依靠面板 100 ms 的 `?` 轮询维持固件 1 秒看门狗。日志采集和断言优先使用串口脚本；窗口操作仅用于必要的界面验收。

|---|---|
| `?` / `h` / `d` / `f` | 状态帧 / 帮助 / 配置 / 驱动故障寄存器 |

| `r` / `R` | 正/反向位置轨迹 1 圈 |
| `p` / `P` | 正/反向无限旋转；方向只能在停止后切换 |
| `#0` / `#1` | SPIN 闭环 / 开环模式（开环力度上限 40%） |
| `V1` / `V2` / `V3` / `V4` | SPIN 速度 0.05 / 0.10 / 0.25 / 1.00 圈/秒（3/6/15/60 rpm） |
| `W1`…`W8` | SPIN 力度上限 10%…80%；其他模式仍受 `MOTION_POWER_PCT_MAX` |
| `o` / `O` | 正/反向开环电矢量推进 1 圈时长 |

| `F` | 读取并清除过流捕获：峰值/计数（over/maxrun/glitch）+ 8 拍冻结快照 |

状态帧以 `#FOC,proto=2,` 开头。`st=0/1/3/4` 分别为待命/运行/故障/完成；`2` 保留，当前没有主动 HOLD 模式。`mode=0/1/2` 分别为普通动作/手动/SPIN；SPIN 时 `pct` 为 10–80 的专属力度上限。`ia/ib/ic` 单位为 ADC LSB，只有 `cal=1` 时表示已减标定零点；`cal=0` 为未标定原始值。`encok/adcok` 标记当前采样有效性，`drvok/aligned/ready` 表示驱动与运动条件，`fault/stage/out/brk` 提供故障、启动阶段和使能诊断。当前是诊断字符协议；除 SPIN 的 1 秒固件看门狗外，完整宿主协议和通用心跳目标尚未实现。

**混合换向（`y`）开机默认关闭（`fw=20261017.11` 起）**：按 `y` 可手动开启；10-17 深夜实测开启后每拍开销超 50 µs 预算，会把控制 ISR 从 20 kHz 拉低到 ~12 kHz、动作实际时长 ×1.67，因此默认关闭，单拍耗时优化仍未完成。详见 [闭环平滑扫描记录](docs/smoothness-2026-10-17.md)。

## 引脚与证据边界

SPI0/1 均为 3.125MHz；DRV 桥 DEPTH32，MT 桥 DEPTH12、下降沿采样。MCU PCLK 显式分频至 100MHz；VE BUSCLK 与其独立。PWM 配置 20kHz，更新 IRQ 按谷底门控，本板 mcycle 实测约20,008Hz；固件以该频率用于计时。

PIN_28 为 INL_ALL，同时是 JNTRST；固件仅释放 NJTRST。若探针电缆把 nTRST 拉低，通电驱动时可能冲突，空闲拉低不能消除运动期间的布线冲突。PIN_24/25 保持调试用途，26/27 留空，BOOT1/PIN_15 保持启动下拉。
